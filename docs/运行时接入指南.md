# Pandora Box 运行时接入指南

> 面向对象:接入方(消费应用)前端工程师
> 目标:把运营在搭建器里搭好的页面,渲染到你的 App 里

---

## 1. 这是什么

运营在**搭建器**(Contentful,内容类型 `pandoraBox`)里用可视化组件拼页面 → 保存成一份**平台无关的 JSON 文档** → 你的 App 用**运行时**(`pandora-box-react`)把它渲染出来。

```
搭建器(Contentful) ──保存──▶ 文档 JSON ──拉取──▶ pandora-box-react 渲染 ──▶ 你的页面
```

运行时是**纯 props、无编辑器、跨端**的:文档里只存"声明"(文本 i18n、点击动作、条件显示、数据绑定、主题 token 引用),真实数据由你的 App 在渲染时注入。这样同一份文档在 Web / React Native 都能渲染,差异只在你注入的适配层。

pnpm add pandora-box-react pandora-box-dp pandora-box-layout pandora-box-manifest

## 3. 快速开始(三步)

### 第 1 步:创建运行时(全局一次)

```tsx
// pandora-runtime.ts
import { createRuntime, type ComponentRegistry, type Manifest } from 'pandora-box-react';
import { manifest } from 'pandora-box-manifest';
import { dpRegistry, DpProvider } from 'pandora-box-dp';
import {
  Flex, Card, Overlay, Positioned, Swiper, Typography,
  MediaCaption, MediaCarousel, HeroOverview, WhatsNew, UpcomingList, ServiceList,
} from 'pandora-box-layout';
import '@dragonpass/atom-ui-mobile/dist/style/style.ga.css'; // dp-design 样式(必须引入)

// registry = dp-design 全量组件 + 引擎模板/原语(与 manifest 对齐)
const registry = {
  ...dpRegistry,
  Flex, Card, Overlay, Positioned, Swiper, Typography,
  MediaCaption, MediaCarousel, HeroOverview, WhatsNew, UpcomingList, ServiceList,
} as unknown as ComponentRegistry;

export const PandoraRuntime = createRuntime({
  registry,
  manifest: manifest as unknown as Manifest,
  wrapper: DpProvider,        // 注入 dp 主题 + 语言上下文
  fallbackLocale: 'en',
  // 点击事件的默认派发器(见 §4.2)
  onAction: (action) => {
    if (action.type === 'navigate' && action.href) {
      window.location.assign(action.href);   // 或你们的路由 / 小程序 openWebview
    } else if (action.type === 'event') {
      // 埋点 / 自定义事件:action.name, action.payload
    }
  },
});
```

### 第 2 步:从 Contentful 拉取文档

```ts
// 已发布内容 → CDA(Content Delivery)只读 token + cdn.contentful.com
export async function fetchPandoraDoc(entryId: string) {
  const space = 'YOUR_SPACE_ID';
  const env = 'master';
  const cdaToken = 'YOUR_CDA_TOKEN';        // ⚠️ 别在前端明文暴露,见下方注意
  const url =
    `https://cdn.contentful.com/spaces/${space}/environments/${env}` +
    `/entries/${encodeURIComponent(entryId)}?access_token=${cdaToken}`;

  const res = await fetch(url);
  if (!res.ok) return null;
  const json = await res.json();
  const content = json?.fields?.document?.content;      // pandoraBox 的 document 字段
  if (!Array.isArray(content) || !content.length) return null;
  return { root: { props: {} }, content };             // 运行时要的 doc 结构
}
```

> **token 安全**:CDA 是只读 delivery token,但仍是密钥。生产环境**建议走你们后端代理**(前端请求你们的接口,后端带 token 请求 Contentful),或用构建期注入 + 服务端渲染,避免前端明文。草稿内容改用 CPA(Content Preview)token + `preview.contentful.com`。

### 第 3 步:渲染

```tsx
import { useEffect, useState } from 'react';
import { PandoraRuntime } from './pandora-runtime';
import { fetchPandoraDoc } from './contentful';

export function PandoraPage({ entryId }: { entryId: string }) {
  const [doc, setDoc] = useState<any>(null);
  useEffect(() => { fetchPandoraDoc(entryId).then(setDoc); }, [entryId]);
  if (!doc) return null;

  return <PandoraRuntime doc={doc} locale="zh" fallbackLocale="en" />;
}
```

到这里,运营在这个 entry 里搭的所有组件就会**整页按顺序渲染**出来。

## 4. 核心能力

运行时的所有能力都是同一个模式:**文档存声明,你在渲染时注入数据 / 提供处理器**。全部通过 `<PandoraRuntime {...props} />` 的 props 传入。

| Prop | 类型 | 说明 |
|---|---|---|
| `doc` | `{ root, content }` | 从 Contentful 拉到的文档(必填) |
| `locale` | `string` | 当前语言,如 `'zh'` / `'zh-CN'` |
| `fallbackLocale` | `string` | 兜底语言,如 `'en'` |
| `flags` | `Record<string, boolean>` | 权益开关,驱动条件显示(§4.3) |
| `bindings` | `Record<string, unknown>` | 数据驱动模块的数据(§4.4) |
| `onAction` | `(action) => void` | 点击事件派发(覆盖 createRuntime 里的默认) |

### 4.1 多语言 i18n

文档里的文本是**短语言码的 map**,如 `{ en: 'Book', zh: '预订' }`。传 `locale` + `fallbackLocale`,运行时按 **精确匹配 → 兜底语言 → 第一个** 的顺序解析。

```tsx
<PandoraRuntime doc={doc} locale="zh-CN" fallbackLocale="en" />
```

### 4.2 处理点击事件 onAction ⭐

这是接入时最常改的一块,单独展开。

#### 事件从哪来

运营在搭建器里给组件(卡片、链接文案、按钮…)配 **On click**,存成一段**Action 描述**(是数据,不是函数)。用户点击时,运行时把它转成一次对你 `onAction(action)` 的调用 —— **具体怎么落地由你的 App 决定**。所以同一份文档,在 H5 / App / 小程序里可以有不同的跳转实现。

#### Action 数据结构

```ts
type Action =
  | { type: 'navigate'; href: string; target?: '_self' | '_blank' }        // 跳转:href = URL 或路由
  | { type: 'event';    name: string; payload?: Record<string, unknown> }; // 自定义事件:name + 数据
```

- **`navigate`** —— 运营配的"跳到某个链接/路由"。`href` 是目标,`target` 可选(`_blank` 新开)。
- **`event`** —— 运营配的"触发一个业务事件"。`name` 是事件名,`payload` 是携带数据;做什么由你按 `name` 分发。

#### 两级配置:全局默认 + 单页覆盖

```tsx
// ① 全局默认:createRuntime 里配一次,所有页面通用
export const PandoraRuntime = createRuntime({ /* …registry, manifest… */
  onAction: (action) => defaultDispatch(action),
});

// ② 单页覆盖:某页要特殊处理时,传 prop(会覆盖全局默认)
<PandoraRuntime doc={doc} onAction={(action) => customDispatch(action)} />
```

#### 场景示例(逐个)

**A. 站内路由跳转(React Router)** —— 外链新开、站内走路由

```tsx
import { useNavigate } from 'react-router-dom';
const navigate = useNavigate();

<PandoraRuntime doc={doc} onAction={(a) => {
  if (a.type !== 'navigate') return;
  if (/^https?:\/\//.test(a.href)) window.open(a.href, a.target || '_self'); // 外链
  else navigate(a.href);                                                     // 站内路由
}} />
```

**B. 站内路由跳转(Next.js)**

```tsx
import { useRouter } from 'next/router';
const router = useRouter();

onAction={(a) => {
  if (a.type === 'navigate') a.target === '_blank' ? window.open(a.href) : router.push(a.href);
}}
```

**C. 外部链接(遵守 target)**

```tsx
onAction={(a) => {
  if (a.type === 'navigate') window.open(a.href, a.target === '_blank' ? '_blank' : '_self');
}}
```

**D. App 内 H5 / 小程序 webview(走桥)**

```tsx
import { openWebview } from '@dragonpass/miniapp-jsbridge'; // 或你们自己的桥

onAction={(a) => { if (a.type === 'navigate') openWebview(a.href, {}); }}
```

**E. 埋点(event 类型)**

```tsx
onAction={(a) => {
  if (a.type === 'event') tracker.track(a.name, { ...a.payload, source: 'pandora' });
}}
```

**F. 按事件名分发到不同业务(领券 / 加购 / 打开弹窗 / 联系客服…)**

```tsx
const EVENT_HANDLERS: Record<string, (p?: any) => void> = {
  openCoupon: (p) => couponModal.open(p?.couponId),
  addToCart:  (p) => cart.add(p?.skuId),
  openEsim:   ()  => esimSheet.open(),
  contactCS:  ()  => im.openChat(),
};

onAction={(a) => { if (a.type === 'event') EVENT_HANDLERS[a.name]?.(a.payload); }}
```

#### 推荐写法:统一 dispatcher(navigate + event 收敛成一个)

把所有落地逻辑集中到一个函数,页面里只管接进去:

```ts
// action-dispatch.ts
type Deps = { navigate: (href: string) => void; open: (href: string) => void; track: (name: string, p?: any) => void };

export function makeDispatch(deps: Deps) {
  const EVENTS: Record<string, (p?: any) => void> = {
    openCoupon: (p) => {/* 领券弹窗 */},
    addToCart:  (p) => {/* 加购 */},
    // …按业务扩展
  };
  return (action: { type: string; href?: string; target?: string; name?: string; payload?: any }) => {
    if (action.type === 'navigate' && action.href) {
      const external = /^https?:\/\//.test(action.href) || action.target === '_blank';
      external ? deps.open(action.href) : deps.navigate(action.href);
      deps.track('pandora_navigate', { href: action.href });
    } else if (action.type === 'event' && action.name) {
      EVENTS[action.name]?.(action.payload);
      deps.track(action.name, action.payload);
    }
  };
}
```

```tsx
const dispatch = makeDispatch({
  navigate: (h) => router.push(h),
  open:     (h) => window.open(h, '_blank'),
  track:    (n, p) => tracker.track(n, p),
});

<PandoraRuntime doc={doc} onAction={dispatch} />
```

#### 对照:搭建器里配了什么 → 运行时收到什么

| 运营在搭建器配的 On click | 运行时 onAction 收到的 action |
|---|---|
| Navigate → `#book-fast-track` | `{ type:'navigate', href:'#book-fast-track', target:'_self' }` |
| Navigate → `https://…`,New tab | `{ type:'navigate', href:'https://…', target:'_blank' }` |
| Event → `openCoupon`(payload `{couponId}`) | `{ type:'event', name:'openCoupon', payload:{couponId} }` |
| On click = None(未配) | 该组件无点击,**不会**调用 `onAction` |

> **两级点击**:整张卡片和卡内链接是**各自独立**的 —— 运营可以给整张 `Card` 配一个 On click,再给里面的 "Book Fast Track" 文案单独配一个。两者都会各自触发 `onAction`(内层通常做更具体的动作)。点内层链接时,若你希望不冒泡触发外层卡片的动作,在你的 `onAction`/桥里做去重或让内层 `event` 短路即可。

### 4.3 条件显示 flags(权益 / entitlement)

运营可以给区块配 `visibleWhen`(引用一个 flag 名,如 `Lounge`、`FastTrack`、`eSIM`)。你把**当前用户的权益**传给运行时,运行时会自动隐藏用户没有的区块:

```tsx
<PandoraRuntime
  doc={doc}
  flags={{ Lounge: true, FastTrack: false, Limo: true, eSIM: true }}
/>
```

- flag = `false` 或缺失 → 对应区块**不渲染**。
- flag 的名字由搭建器里配的决定,和你们服务端下发的权益字段对齐即可。

### 4.4 数据驱动模块 bindings

有些模板(如 `UpcomingList`、`ServiceList`)是**数据驱动**的:文档里只存"绑定描述 + 一份示例数据",真实数据由你注入:

```tsx
<PandoraRuntime
  doc={doc}
  bindings={{
    // key = 搭建器里配的绑定 source id;value = 你的真实数据
    upcomingSource: [{ title: '...', time: '...' }, /* ... */],
  }}
/>
```

> 未注入时模块显示搭建器里的静态示例数据,不会报错。

### 4.5 白标换肤(design token)⭐

运行时里所有组件(文字、链接色、**卡片表面 / 描边**)都读 dp-design 的语义 token(`--aum-*` CSS 变量)。你用 `@dragonpass/atom-ui-mobile` 的 `ConfigProvider` 配**租户主题的 token 值**,整页就自动换肤 —— 无需改文档、无需改组件:

```tsx
import { ConfigProvider } from '@dragonpass/atom-ui-mobile';

<ConfigProvider
  biz="your-tenant"
  theme={{
    token: {
      primaryColor: '#7B1FA2',          // 主色(文字/主强调)
      primaryInverseColor: '#FFF7FA',   // 卡片 / 容器表面色
      linkColor: '#7B1FA2',             // 链接色
      borderDefaultColor: '#EADFF0',    // 描边
      // ……其它 dp 语义 token
    },
  }}
>
  <PandoraRuntime doc={doc} locale="zh" />
</ConfigProvider>
```

- 原理:`ConfigProvider` 会把 token 值注入成全局 `--aum-*` CSS 变量;组件用 `var(--aum-*)` 读取,所以**改 token = 全页换肤**。
- 常见白标 token:`primaryColor`(主色)、`primaryInverseColor`(卡片表面,默认 `#FFFFFF`)、`linkColor`(链接)、`borderDefaultColor`(描边)、`bgDisabledColor`(占位/骨架)等。
- 需要 `pandora-box-layout ≥ 0.1.19` 才能让**卡片表面**也跟随换肤(更早版本只有文字层跟随)。

## 5. 完整示例

```tsx
// PandoraContainer.tsx —— 一个可直接用的容器组件
import { useEffect, useState } from 'react';
import { ConfigProvider } from '@dragonpass/atom-ui-mobile';
import { PandoraRuntime } from './pandora-runtime';
import { fetchPandoraDoc } from './contentful';

interface Props {
  entryId: string;                       // Contentful pandoraBox entry id
  locale?: string;                       // 当前语言
  flags?: Record<string, boolean>;       // 用户权益
  bindings?: Record<string, unknown>;    // 数据驱动模块数据
  theme?: { token: Record<string, string> }; // 白标主题 token
  onAction?: (a: any) => void;           // 点击派发
}

export function PandoraContainer({ entryId, locale = 'zh', flags, bindings, theme, onAction }: Props) {
  const [doc, setDoc] = useState<any>(null);
  useEffect(() => {
    let alive = true;
    fetchPandoraDoc(entryId).then((d) => alive && setDoc(d));
    return () => { alive = false; };
  }, [entryId]);

  if (!doc) return null;

  const page = (
    <PandoraRuntime
      doc={doc}
      locale={locale}
      fallbackLocale="en"
      flags={flags}
      bindings={bindings}
      onAction={onAction}
    />
  );

  return theme ? <ConfigProvider theme={theme}>{page}</ConfigProvider> : page;
}
```

用法:

```tsx
<PandoraContainer
  entryId="2xe2LGcBEwGPPOtFyfFA6H"
  locale="zh-CN"
  flags={{ eSIM: true, FastTrack: true }}
  theme={{ token: { primaryInverseColor: '#FFF7FA', linkColor: '#7B1FA2' } }}
  onAction={(a) => a.type === 'navigate' && router.push(a.href)}
/>
```

## 6. 组件清单

- **引擎模板 / 原语**(`pandora-box-layout`):`Flex`、`Card`、`Overlay`、`Positioned`、`Typography`、`Swiper`、`MediaCarousel`、`MediaCaption`、`HeroOverview`、`WhatsNew`、`UpcomingList`、`ServiceList`
- **dp-design 组件**(`pandora-box-dp`):67 个(`Button` / `Image` / `Tag` / `Bill` / `NavHeader` / `Form` 等,与 `manifest` 对齐)

> registry 里两者都 spread 进去即可(见 §3 第 1 步)。运营在搭建器里能用的组件,你这边就要注册齐,否则该组件渲染不出来。

## 7. 注意事项 / FAQ

- **版本必须配套**:`react 0.4.0` / `layout 0.1.19` / `dp 0.2.1` / `manifest 0.2.9`。升级其一时,确认 `manifest` 与 `registry` 仍对齐。
- **文档平台无关**:同一份 `doc` 在 Web / React Native 都能渲染,差异只在 `wrapper`(平台的 Provider)和 `onAction`(平台的跳转/事件)。
- **拉不到内容 / 空白**:检查 `fields.document.content` 是否非空、CDA token / space / environment 是否正确、entry 是否已发布(未发布要用 CPA + preview host)。
- **样式不对 / 没主题**:确认引入了 `@dragonpass/atom-ui-mobile/dist/style/style.ga.css`,且 `wrapper: DpProvider` 已设置(运行时要在 dp 主题上下文里渲染)。
- **换肤不生效**:确认 `pandora-box-layout ≥ 0.1.19`,且 token 是在**包裹运行时的 `ConfigProvider`** 上配的。
